# L03 交付罗盘

在线预览：<https://varien123.github.io/l03-delivery-compass/>

一个针对 **小鹏 MONA L03 超级增程 1330 Max** 的个人提车预测工具。它会**每天自动抓取**公开信源、抽取交付/产能信号、自动校准模型，然后重建网页。你不需要每天手动填样本。

> 订单：2026-11-01 成都锁单 · 新月银 · 18 英寸 · APP 显示 11–16 周  
> 当前结论：**中心估计 2027-02-01**；P10–P90 约 **2027-01-22 – 2027-02-25**；春节前概率 **58%**。  
> 自动更新已启用：每天 09:00；当前已抓取 24 条信源、8 条车友样本，自动校准 **+0.11 周**。

产品形态参考了「徐同学助手」的思路：按锁单日期追踪配车/下线、社区样本、每日进度。但本工具**不抓取也不依赖它的非公开数据**，只用公开信源和本地可核对样本。

## 1. 直接打开

双击 `index.html` 即可。它是**单文件、零依赖**的静态页面，所有数据、样式、图表脚本都内嵌在里面。

如果浏览器对 `file://` 的本地存储限制较多，可以在项目目录启动本地服务：

```powershell
python -m http.server 8765
```

然后访问 `http://127.0.0.1:8765/index.html`。

> 不装 Python 也能看网页；只有“自动抓取/重建”需要 Python。

## 2. 当前预测

| 指标 | 结果 |
|---|---|
| 官方 APP 窗口 | 2026-11-01 + 11–16 周 |
| 中心估计（P50） | **2027-02-01（周一，锁单后 13.0 周）** |
| 乐观（P10） | 2027-01-22（11.7 周） |
| 保守（P90） | 2027-02-25（16.6 周） |
| 春节前 / 春节后 | **58% / 42%** |
| 自动校准 | **+0.11 周**（L03 10 月交付 2 万台、社区样本 13 周） |
| 置信度 | 64%（中等偏上） |

为什么不是简单取 13.5 周的中点：

- 官方窗口是“保守排队口径”，通常会覆盖春节；
- 2027 年春节是 **2 月 6 日**，工厂/物流在 **2/4–2/18** 附近降速，交付会分成“年前”和“年后”两簇；
- 所以模型给出的是**双峰分布**：中心可以落在年前，但尾部会诚实地延伸到年后。

> 这只是个人决策辅助，不是小鹏官方交付承诺。实际以交付顾问通知和 APP 状态为准。

## 3. 自动更新怎么工作

### 3.1 每天 09:00 的运行链路

```text
09:00 Windows 计划任务
  → auto_update.py
    → 小鹏官网资讯（官方 A）
    → IT之家 RSS（媒体 B）
    → Google News RSS 多关键词（媒体 B/C）
    → 小鹏社区 L03 提车帖（社区 C）
  → 标题/正文抽取：L03 月交付、集团月交付、增程/纯电周期、产能节点
  → 事件聚类 + 去重 + A/B/C 分级
  → 更新 sources / community
  → 自动校准 model.calibration.weeks
  → 重建 index.html + 当日快照 + 自动日志
```

已注册 Windows 计划任务：

```text
任务名：L03-Delivery-Compass-Auto-Update
时间：每天 09:00（本机时区）
状态：Ready
```

每次更新完成后，`auto_update.py` 会自动：

- 重建 `index.html` 和当日快照；
- 如果当前目录是 git 仓库且配置了 `origin`，自动 `git add / commit / push` 到 GitHub；
- GitHub Pages 随之刷新，线上版本与本地同步。

查看/立即运行/删除：

```powershell
Get-ScheduledTask -TaskName 'L03-Delivery-Compass-Auto-Update'
Start-ScheduledTask -TaskName 'L03-Delivery-Compass-Auto-Update'
Unregister-ScheduledTask -TaskName 'L03-Delivery-Compass-Auto-Update' -Confirm:$false
```

重新安装（换电脑或任务丢失时）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install_task.ps1
```

> 计划任务以当前 Windows 用户运行；电脑需开机/联网。若 09:00 没开机，Windows 的 `StartWhenAvailable` 会在下次可用时补跑。

### 3.2 手动触发一次

```powershell
python auto_update.py
```

只看抓到了什么、不写数据：

```powershell
python auto_update.py --dry-run --verbose
```

只更新 `data.json`，不重建网页：

```powershell
python auto_update.py --no-build
```

只更新本地，不提交到 GitHub：

```powershell
python auto_update.py --no-push
```

### 3.3 抓取源

| 源 | 级别 | 抓什么 | 失败时 |
|---|---|---|---|
| 小鹏官网资讯 `xiaopeng.com/news` | A | 月度交付、官方新闻 | 保留其他源 |
| IT之家 RSS `ithome.com/rss` | B | 小鹏/L03 快讯与正文 | 跳过 |
| Google News RSS | B/C | 多关键词发现官方/媒体/社区报道 | 可能被网络限制；跳过 |
| 小鹏社区 `bbs.xiaopeng.com` | C | L03 提车帖，抽取锁单→提车 | 跳过 |

说明：

- **不调用付费 API**，只用公开 RSS/网页；
- Google News 在部分网络环境可能不可用，其他源仍会工作；
- 同一事件会被聚成一个 key（例如 10 条“L03 10 月交付 2 万”只保留最有价值的一条）；
- 社区样本标为 `auto: true`，权重低，页面会显示“自动”标签；
- 自动抓取失败不会破坏已有数据；每次运行前会备份到 `backups/`。

### 3.4 人工补充（可选）

自动抓取抓不到、或你知道更准确的样本时，仍可在网页「自动更新」区域下方手动补充：

- 车友样本：锁单日期、提车/配车日期、版本、城市、来源链接；
- 新信源：日期、级别、来源、标题、链接、结论；
- 导出更新包 → `python update.py --merge l03-update-YYYY-MM-DD.json`。

人工数据不会被自动抓取覆盖；`sources` 里会区分手动/自动。

## 4. 模型怎么算

### 4.1 三层证据

| 证据 | 权重 | 作用 |
|---|---:|---|
| 官方 APP 周期 11–16 周 | 55% | 最强先验，接近真实排队口径 |
| 已完成车友样本 | 25% | 校准“官方窗口偏保守”的程度 |
| 产能/供需（L03 月交付 2 万+） | 20% | 解释队列是在缩短还是拉长 |
| 颜色/城市/出口/L05 修正 | 小幅 | 银色、成都、出口分流、L05 独立产线 |

### 4.2 春节双峰

普通正态分布会把春节前后的交付“抹平”，不符合实际。这里用混合分布：

- **年前分量**：锁单后约 12.25 周为中心，截断在 2 月 3 日；
- **年后分量**：锁单后约 15.9 周为中心，从 2 月 19 日（节后复工）开始；
- 权重 **58% / 42%**，由官方窗口、产能和春节停摆共同决定。

再把落在周末/春节停摆日的日期顺延到下一个可交付工作日，得到页面展示的日期。

### 4.3 自动校准

每天抓到的信号会进入 `model.calibration`，并**同时作用于年前/年后两个分量**：

```text
capacityWeeks = (22,000 - L03 最新月交付) / 10,000 × 0.4
windowWeeks   = (增程周期中值 - 13.5) × 0.15
cohortWeeks   = (自动样本平均等待 - 12.6) × 0.08
riskWeeks     = (负面关键词 - 正面关键词) × 0.06
total         = clamp(四项之和, -1.2, +1.2 周)
```

以当前数据为例：

- L03 10 月交付 **20,000 台** → `+0.08 周`（略慢于 2.2 万基准）
- 自动样本 7/31 → 10/30，**13.0 周** → `+0.03 周`
- 增程周期未抓到 → `0`
- 风险词未命中 → `0`
- **合计 +0.11 周**

校准值会显示在页面顶部“置信度”下方，以及「情景沙盘」说明里。它不是黑盒：每次自动更新都会把四项拆解写进 `auto_log.json`。

### 4.4 置信度

64% 不是“64% 会提车”，而是对**当前区间**的信心：

- 官方窗口明确（+）；
- L03 月交付已连续 3 个月增长（+）；
- 同配置已完成样本仍少（−）；
- 出口分流、春节排产、芯片供应仍有不确定性（−）。

## 5. 信源分级

| 级别 | 含义 | 例子 |
|---|---|---|
| **A** | 官方/政府/高管原话 | 小鹏官网、姜文微博、广东省能源局 |
| **B** | 主流媒体/可核对报道 | IT之家、CNMO、36 氪、搜狐、新浪、汽车之家 |
| **C** | 社区/第三方分析 | 小鹏社区、徐同学助手、Reportify |

自动抓取会优先 A/B；C 级只用于车友样本和方向性判断。第三方产能测算始终标注“非官方”，不与官方口径混用。

## 6. 文件结构

```text
.
├─ index.html                 # 最终交付物：单文件网页（数据/样式/脚本全内嵌）
├─ data.json                  # 唯一数据源：订单、模型、产能、样本、信源、自动信号
├─ template.html              # 页面模板（含 __DATA_JSON__ 占位）
├─ app.js                     # 前端逻辑：预测、图表、录入、localStorage、导出
├─ model.py                   # Python 预测模型（与前端同口径）
├─ update.py                  # 构建/合并/快照/检查
├─ auto_update.py             # 自动抓取 + 自动校准 + 重建
├─ auto_update.bat            # 手动双击运行（带日志）
├─ install_task.ps1           # 注册每天 09:00 的 Windows 计划任务
├─ auto_log.json              # 最近一次自动抓取的明细
├─ backups/                   # 每次自动更新前的 data.json 备份
├─ snapshots/                 # 每日快照
│  └─ 2026-11-04.json
└─ README.md
```

`index.html` 是生成物：不要直接改它，改 `data.json` / `template.html` / `app.js`，然后运行 `python update.py` 或 `python auto_update.py`。

## 7. 常见问题

**Q：真的不需要我手动填？**  
A：不需要。计划任务每天 09:00 自动抓取、校准、重建。网页里的表单只是“补充/修正”入口。

**Q：自动抓取会不会把传闻当事实？**  
A：不会直接当事实。只有 A/B 级媒体和可核对标题会进入信源；社区样本标为 `auto`、低权重；同事件会聚类去重。模型只从标题/正文里抽取明确数字。

**Q：Google News 被墙怎么办？**  
A：其他三个源仍工作；抓取错误会写入 `auto_log.json`，已有数据不受影响。也可以把其他 RSS 加到 `auto_update.py` 的适配器列表。

**Q：为什么自动校准只有 ±1.2 周？**  
A：防止单日噪声把预测大幅拉飞。真正的结构性变化（官方周期改变、产能大幅提升）仍以官方窗口和春节双峰为主。

**Q：GitHub Pages 地址是什么？**  
A：<https://varien123.github.io/l03-delivery-compass/>。仓库：<https://github.com/Varien123/l03-delivery-compass>。

**Q：网页里手动录入的数据会直接改 `data.json` 吗？**  
A：不会。网页只存本机浏览器，需要导出更新包，再运行 `python update.py --merge` 合并。

**Q：可以改成其他车型/其他订单吗？**  
A：可以。改 `data.json` 里的 `order`（车型、配置、颜色、城市、锁单日、APP 窗口）和 `model` 参数，再运行 `python update.py`。自动抓取关键词在 `auto_update.py` 顶部的 `GOOGLE_QUERIES` 里。

## 8. 边界

- 车友样本存在幸存者偏差：提前提车的人更愿意发帖。
- 颜色/配置会影响批次；新月银、18 英寸的样本不足，修正幅度刻意保守。
- 出口占比、芯片供应、L05 订单分流都可能让实际日期偏离 1–2 周。
- 交付中心所在城市、尾款/保险/上牌准备也会影响“下线 → 提车”的 3–7 天。
- 自动抓取依赖公开页面结构；页面改版会导致某个源失效，但不会破坏已有数据。

**用途是帮你安排时间、判断是否要联系交付顾问，不是替代官方承诺。**
